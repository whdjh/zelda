# 제품·기술 확정 의사결정 기록 (ADR-lite)

> 결정일: 2026-11-08. **확정**은 사용자와 논의한 기본 원칙. 라이브러리 설치 호환성, 실제 게임 공략, 운영 비용은 실행 시 검증.

## ADR-001 — 출시 제품은 '시오 일반인 하이패스'

- **상태: 확정.** 스피드런·100% 수집이 아니라 글리치 없이 안정적으로 빠른 엔딩 + 퍼즐 단계별 힌트.
- 첫 출시 시오만. 야숨·왕눈의 구체 루트는 추후 사용자 경험 기반으로 추가.

## ADR-002 — SEED + Tailwind v4; 공통 토큰 중복 생성 금지

- **상태: 확정.** 기본 UI는 SEED Design React; CSS는 Tailwind CSS v4와 공식 `@seed-design/tailwind4-theme` 연동. SVG/노선 애니메이션처럼 Tailwind가 부자연스러운 범위에서만 CSS Modules.
- 색·간격·타이포·라운드·모션은 **SEED 기존 scale/semantic 토큰 우선**. 토스의 3단계 구조를 별도 구현하지 않음. 노선도 고유 상태 값이 부족할 때만 제한적 컴포넌트 커스텀 토큰 추가.
- 테마는 시오 분위기에서 영감 받되 닌텐도 UI/브랜드 자산을 모방하지 않음.

## ADR-003 — React 기본 상태 관리 우선

- **상태: 확정.** 로컬은 `useState`. 서로 떨어진 자식에서 동일 진행도를 읽거나 실질적 props drilling이 나타날 때만 `useContext` 도입.
- **초기 Jotai/Zustand 채택 취소.** 현재 복잡도와 실제 필요가 확인되지 않았으므로 사용하지 않는다.
- 공유가 필요하더라도 Context를 한 개 거대 저장소로 만들지 않고 최소 범위에서 사용.

## ADR-004 — 로그인/서버 없음 + 로컬 백업 (폐기, ADR-011로 대체)

- **상태: 폐기.** 초기 합의는 서버/인증을 제외했으나, 최신 사용자 요청이 로그인과 DB 기반을 명시했다. 로컬 백업 원칙만 유지하고 서버 제외 결정은 ADR-011로 대체한다.

## ADR-005 — 추천 경로의 수동 수정과 규칙 재계산

- **상태: 초기 기능 확정.** 사용자가 완료한 역·필요한 보유 조건을 수정할 수 있고, **정적 검증된 선행 관계**를 따라 남은 추천 루트·잠금 상태가 갱신된다.
- 노선 좌표는 기본적으로 안정적으로 유지. 미래의 AI 개인화 경로/동적 레이아웃은 추후 검증 대상이며 초기 범위 아님.

## ADR-006 — 스포일러와 퍼즐 힌트

- **상태: 초기 기능 확정.** 기본은 완료/현재/다음 목적지만 명확히 공개, 미래 구간은 잠금/이름 비노출. 필요 시 엄격·전체 공개 설정.
- 퍼즐 1(관찰) → 2(구체 단서) → 3(해법) 단계별 명시적 요청. 블러는 장식일 뿐 실제 숨김을 대신하지 않음.

## ADR-007 — 미디어는 핵심 요구가 아님

- **상태: 확정.** 최초 출시는 텍스트/자체 제작 단순 도식으로 완결. 직접 녹화 GIF·영상은 필요성 확인 후 권리 검토를 거쳐 도입.

## ADR-008 — 공략 조사 → 플레이 수정

- **상태: 확정.** 기존 공략의 **사실** + 독립 출처 비교를 통한 **추천 루트 추론**으로 초안을 만들고, 사용자 직접 플레이로 계속 수정한다.
- 검증 상태(`proposed/cross_checked/playtested/compared`) 명시. 직접 확인하지 않은 공략·영상 내용을 확인한 척하지 않음.

## ADR-009 — 재사용 가능한 컴포넌트, 불필요한 추상화 금지

- **상태: 확정.** 도메인 책임 있는 RouteMap/RouteStop/HintReveal 등만 추출. SEED 래퍼/미래 확장만을 위한 abstraction 및 과한 계층 금지.

## ADR-010 — 분석과 SEO

- **상태: 방향 확정.** 각 문제/역 검색 유입 + 앱형 진행 경험을 결합. Search Console 및 개인정보/동의 검토 후 GA4. MAU는 고유 사용자 수이며 방문 횟수가 아님.

## 확정되지 않은 항목

서비스명 상표 가능성, 실제 출시일, 수익 모델, 시오 최적 경로, OAuth 공급자/AI 모델, 초반 PWA 설치·오프라인 캐싱 세부 시점, 원격 인프라 요금/리전은 별도 검증·결정한다. 설치 버전은 package-lock.json에 고정한다.

## ADR-011 — Next.js 서버 기능 + Supabase (현재 채택)

- **상태: 최신 사용자 요구에 따라 채택.** 별도 서버 없이 Server Actions/Route Handlers와 Supabase Auth/PostgreSQL을 사용한다.
- 해결 문제: 사용자별 완료·힌트 기록 보관과 기기 간 이어하기. 로컬 사용/JSON 백업은 병행한다.
- 사용자 ID는 서버 인증에서 얻고 RLS를 적용한다. 저장은 revision으로 동시 변경을 확인하며 자동 병합하지 않는다.
- 정적 게임 콘텐츠와 사용자 진행 데이터를 분리한다. game_id/game_version/contentVersion/schemaVersion을 기록하되 AI 실행/벡터 DB/범용 엔진을 미리 도입하지 않는다.
- 기본 로그인은 OAuth Secret이 필요 없는 이메일 링크다. OAuth는 공급자가 정해지면 별도 추가한다.
- 사용자 계정에서 프로젝트 생성·메일 설정·마이그레이션 적용·실제 RLS 검증은 아직 필요하다.

## ADR-012 — 초기 개발·검증 도구

- Node 24 + npm, Next.js 16/React 19, TypeScript 5.9, SEED 3, Tailwind 4. 설치 상세 버전은 package-lock.json 참조.
- SEED 공식 seed-layered 모듈 조건을 적용하기 위해 dev/build 모두 Webpack을 사용한다. 새 토큰 체계를 만들지 않는다.
- 순수 로직은 Node 내장 테스트, 브라우저는 Playwright. ESLint는 Next 설정의 React/import 플러그인이 지원하는 9.x를 사용한다. 10.x는 현재 peer 범위 밖이므로 채택하지 않는다.
- 외부 서비스 설정이 없을 때도 타입 검사·빌드·공개 화면·로컬 저장이 동작해야 한다. 실제 인증/DB 통합 검증과 구분해 보고한다.

# 모바일 UX·정보 구조 — 최종 방향

> 현재는 전체 공략 제작과 비로그인 이용이 우선이다. 아래 /login 및 서버 기록은 후속 연결용 준비 경로이며 기본 홈의 사용 흐름에서 제외한다.

## 기본 UX 약속

**'현재 내가 어디고, 지금 무엇을 해야 하며, 막히면 어느 정도만 도움받을까?'**를 폰에서 짧게 해결. 복잡한 위키/수집 모드 화면은 최초 사용자 경험에 섞지 않는다.

## 정보 구조

```text
/oot (현재 모험 요약)
 ├── /oot/route (현재역 중심 세로 노선도)
 │    ├── 역 탭 → SEED Bottom Sheet: 목표 / 최대 3문장 / 준비물 / 완료·되돌리기
 │    │    └── 퍼즐 선택 → 힌트 1 → 힌트 2 → 해법 3
 │    ├── 완료/미완료 수정 → 남은 추천 경로 재계산 → 강조 변경
 │    └── 현재 위치 직접 선택(충돌 시 확인)
 ├── /oot/puzzles/[id] (검색용 스포일러 없는 진입)
 ├── /login → /auth/callback: 이메일 링크 인증
 └── 설정: 스포일러 / 백업·복원 / 서버 기록 / 로그아웃 / 비공식 고지
```

## 홈/노선도

- 작은 화면: **세로 스크롤형 지하철 노선**, 현재역 자동 포커스(단, 사용자 수동 스크롤을 강제로 다시 옮기지 않음).
- 역 수를 적당히 묶는다. 던전 내부 작은 퍼즐을 모두 역으로 만들지 않고, 해당 주요 역의 상세 문제 목록에 넣는다.
- 필수역=본선, 시간이 절약된다는 근거가 있는 추천역=작은 지선, 기본 생략 가능 콘텐츠=첫 화면 비노출.
- 분기·합류는 실제 게임 제약을 조사해 설계. 완료역·현재역·잠금·추천은 색+아이콘+텍스트 병용.

## 역 Bottom Sheet

- 필드 순서: 현재 상태 → 목표 → **최대 3개 짧은 행동 문장** → 필수 준비물(있을 경우) → 추천 경유 이유 → '막혔나요?' → 완료/완료 취소.
- 3문장 요약에 퍼즐의 **정답 동작**이 섞이지 않도록 한다. 세 문장은 목표 수준의 행동(어디·무엇을 준비·어떻게 확인)이지 마지막 퍼즐 해답을 미리 공개하는 칸이 아니다.
- 선행 조건을 충족하지 않고 완료로 표시했으면 사용자 기록을 덮어쓰지 않고 충돌과 선택지를 보여준다.

## 스포일러 수준

| 설정 | 표시 방식 |
| --- | --- |
| **엄격(strict)** | 완료/현재 구간 외엔 '미발견 역' 또는 잠금·숫자만. 다음 구간도 정체 최소 노출 |
| **기본(default)** | 완료/현재 + **다음 목적지 이름까지만**. 이후는 중립 잠금·블러형 실루엣 가능, 실제 텍스트는 렌더하지 않음 |
| **전체(full)** | 사용자가 명시적으로 선택할 때 모든 역 이름/가이드 접근 허용. 힌트/정답 공개는 별도 동작 유지 |

- 블러는 **빈 실루엣/장식 영역**에만 사용할 수 있다. 스포일러 문장을 CSS blur나 `display:none`으로 숨겨둔 채 DOM/접근성 트리에 두지 않는다.
- 검색 엔진에 보여주는 메타/OG/기본 HTML은 스포일러 없는 소개만. 명시적 요청 전에는 정답 컴포넌트를 렌더하지 않는다.
- 설정 변경 및 미래 역 직접 링크 진입 시 콘텐츠 공개 전 확인을 요구.

## 진행도 수정과 경로 UI

- 사용자가 완료/취소·보유 조건을 수정하면 검증된 선행 규칙으로 **새 다음 목표**를 계산한다.
- 노선 자체가 갑자기 재배열되면 위치 기억이 깨지므로 초기에는 좌표/기본 순서를 유지하고 **굵기·현재 위치·잠금·추천 여부만 재표현**한다.
- 이미 예상과 다른 구간을 완료했으면 충돌 고지 + 직접 수정 흐름. AI 판단/자동 완료 금지.

## 방문 복원과 백업

- 로그인 없이 진행도와 힌트 해금·스포일러 설정을 localStorage에 저장. 저장에 실패하면 사용자에게 알려준다.
- 현재는 JSON 내보내기/가져오기를 제공하고, 선택 로그인 후 서버 저장/가져오기는 후속으로 연결한다. 자동 동기화/병합은 하지 않으며 기존 로컬/서버 기록 교체는 명시적 선택으로 처리한다.
- 기기·브라우저 저장소를 삭제하면 데이터가 유실될 수 있다고 설명.

## 접근성·사용성 목표(시험해야 할 가설)

- 처음 방문 시 현재 목표를 5초 안에 파악할 수 있는지 모바일 사용성 실험.
- 주요 목표·완료를 색만으로 판단하지 않음, 키보드·스크린리더에서도 역 선택/힌트 단계 제어.
- 360/390px와 확대, safe area, 모션 감소 대응.

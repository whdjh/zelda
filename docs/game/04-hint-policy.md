# 스포일러·점진적 힌트 정책 — 확정

## 핵심 분리

- **노선 스포일러:** 미래 스토리/구간/보스 이름을 얼마나 보여줄까? → 설정 `strict/full`(이전 default는 full로 읽음).
- **퍼즐 힌트:** 사용자 요청 수준만 공개. 루트 전체 공개를 골라도 **퍼즐 해법이 자동으로 나타나지는 않는다**.
- **최대 3개 행동 문장:** 목표·이동·준비를 말하지만 퍼즐의 구체적 정답을 먼저 제공하지 않는다.

## 퍼즐 단계

| 단계 | 역할 | 예시(허구, 실제 시오 퍼즐 아님) |
| --- | --- | --- |
| 기본 | 무엇이 목표인지 | '잠긴 방에서 반대편으로 이동하세요.' |
| **힌트 1** | 주의할 환경 | '벽면과 천장을 둘러보세요.' |
| **힌트 2** | 기믹 방향 | '벽 위 작은 장치와 갖고 있는 원거리 도구를 연결해 보세요.' |
| **해법 3** | 정확한 행동 | '원거리 도구로 해당 장치를 맞혀 문을 엽니다.' |

- 각각 **독립 클릭**으로 해금. '바로 정답 보기'는 별도 명확한 선택 허용.
- 모든 퍼즐을 억지로 3개로 늘리지 않는다. 단순한 상황은 1~2단계도 가능하지만 UI는 가장 뒤 단계가 해법임을 일관되게 알림.
- 저장된 힌트 공개 상태는 새로고침 후에도 재현 가능. 공개 이후 다시 가리는 동작을 지원할지 사용성 검토.

## 스포일러 표시 규칙

- 기본은 전체 노선 공개다. strict 설정에서만 완료/추천 구간 외의 이름을 가린다. 미래 이름/해법이 있는 실제 텍스트를 블러 처리한 채 DOM에 유지하지 않는다.
- `aria-hidden`, 접근성 트리, HTML meta, 검색 결과 요약, OG 텍스트/이미지, 미리보기의 누출을 각각 점검한다.
- 노선 가림 효과는 심미적 블러 또는 실루엣일 수 있지만 **정보 비노출 로직이 우선**.
- 사용자 설정 `full`은 전체 노선 이름을 열람하는 것이며 정답 자동 노출 동의가 아니다.

## 공략 검증

3단계 해법에 오류가 있으면 정확하지 않은 내용을 공개하지 않는다. 출처 2개 교차 확인과 판본 구분, 직접 플레이를 통해 수정한다. 저작권 미확인 GIF/영상 대신 자체 문장·도식 사용.

## UX 테스트

- 힌트 1만 봐도 바로 답을 알게 되는가? → 과도한 노출 가능성.
- 힌트 2가 실질적 도움이 되는가? → 무의미한 단계 삭제.
- 해법 3이 게임 버전과 정확히 맞는가?
- 사용자가 스포일러 수준을 변경해도 원치 않는 정보가 갑자기 보이지 않는가?

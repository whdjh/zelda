# 후속 기능 로드맵 — 지금 만들지 않을 것까지 경계 지정

> 이 문서는 **확정된 미래 구현 약속이 아니라 사용자가 제안한 확장 방향의 기록**이다. 출시 첫 버전의 코드에 미리 범용 추상화를 추가하지 않는다.

## Phase 1 — 시오 스토리 하이패스 (현재 범위)

- 전체 엔딩 루트의 필수/추천 경유 정리와 근거 관리.
- 세로 노선도, 역 행동 요약, 단계별 퍼즐 힌트.
- 전체 스토리·던전·보스·퍼즐의 자체 공략, 로컬 완료·힌트 기록과 **규칙 기반** 다음 추천 루트 반영. 로그인 연결은 공략 이후로 미룬다.
- 스포일러 수준, JSON 백업·복원, 한국어 검색 진입.
- 직접 플레이할 때마다 데이터·순서·힌트를 고쳐 신뢰도를 높인다.

## Phase 2 — 수집/완전 클리어 모드

- 스토리 하이패스와 분리된 **100% 모드**. 하트/스컬툴라/서브퀘스트 등은 데이터 조사 후 범위 결정.
- 기본 하이패스 화면에 수집품을 섞어 핵심 경험을 복잡하게 만들지 않는다.
- 기존 스토리 진행도를 활용할 수 있는지 콘텐츠 선행 관계를 보고 설계한다.

## 서버 기록의 현재 범위와 후속 범위

Supabase 기술 선택과 기존 준비 코드는 유지하되, 최신 사용자 지시(ADR-013)에 따라 로그인 연결은 전체 공략 제작 이후로 미뤘다.

- 후속 연결용 준비 코드: 이메일 링크 로그인, 사용자별 진행/힌트 스냅샷, RLS, 명시적 서버 저장/가져오기, 버전 충돌 거부.
- 비로그인 로컬 기록은 유지한다. 로그인만으로 로컬/서버 기록을 자동 교체하지 않는다.
- 후속: OAuth 공급자 선택, 실시간 동기화, 자동 병합, 계정 삭제 UI. 계정·이메일·개인정보 처리와 탈퇴 절차 검토는 공개 전 필요하다.
- 실제 연결·권한 시험은 [설정 안내](../development/03-supabase-setup.md)를 따른다.

## Phase 4 후보 — AI 개인화 경로와 동적 배치

도입 조건: 고정 추천 루트가 사용자 실력/현재 보유 아이템/선행조건 변화에 충분히 대응하지 못한다는 실제 근거.

- AI는 **검증된 게임 ID·조건만** 골라 새 후보 루트를 추천. 실패/불가능 경로는 규칙 엔진 검증으로 차단.
- 추천 이유, 생략한 경유, 위험과 추정 시간 근거를 보여준다.
- 'AI가 레이아웃을 바꾼다'는 아이디어는 후보로 기록. **즉시 화면 재배치보다** 변경된 경로를 deterministic UI로 표현하는 방식을 우선 실험한다.
- AI가 임의의 노선 SVG 좌표나 HTML/CSS를 생성하는 것은 접근성/예측 가능성·오류 위험이 있으므로 후속 별도 평가.
- 계정은 동기화에, AI는 개인화에 필요한 것으로 **별도 의존성**이다. 둘 중 하나가 다른 것의 필수 조건은 아니다.

## 장기 — 야숨/왕눈

사용자의 직접 게임 경험을 바탕으로 **준비물·성장·전투 위험까지 포함한 일반 플레이어 최적 루트** 철학을 확장한다. 구체 사당/무기/요리 루트는 현재 문서에 추가하지 않는다. 작품별 차이를 확인한 뒤 데이터 모델의 공통화 범위를 판단한다.

## 미디어

직접 제작한 그림/짧은 영상이 꼭 필요한 퍼즐에만 선택적으로 추가. **자체 캡처도 저작권 이용 허락을 자동으로 부여하는 것은 아님**. 게시·광고·배포 범위를 권리 검토한 후 사용.

# 진행도·상태 저장·규칙 기반 경로

## 구분

| 데이터 | 위치 |
| --- | --- |
| 게임 사실·출처·판본·힌트 본문 | 정적 content 폴더 |
| 선택 역·열린 시트·백업 확인·통신 상태 | 해당 UI의 useState |
| 브라우저 완료·조건·힌트 ID·스포일러 | useProgress + localStorage v1 |
| 로그인 사용자·인증 쿠키 | Supabase Auth + SSR 클라이언트 |
| 사용자별 서버 진행도·힌트 ID | user_progress 스냅샷 + revision |

## 규칙 계산

src/lib/route-selection.ts의 selectRoute는 완료 ID와 **직접 확인한** 보유 조건으로 선행 조건을 검사한다. 정적 배열 순서에서 도달 가능한 필수/추천 역을 현재 후보로 선택한다. 다음 후보는 현재 역을 마친 상태를 가정해 선행 역만 검사하되 아이템 획득을 추정하지 않는다.

- 완료된 역은 기록으로 보존하고 선행 역을 자동 완료하지 않는다.
- 이미 완료한 역의 선행 조건이 빠지면 conflictIds로 반환한다. 사용자에게 완료·보유 조건을 확인하도록 안내한다.
- 선택역은 기본 추천에서 제외한다. 추천 경유의 정교한 이득/비용 재평가는 실제 콘텐츠 조사 후 추가한다.
- 소년/청년·시간대 같은 실제 조건이 단순 역/아이템 모델로 부족하면 근거를 조사한 뒤 모델을 변경한다. 현재 함수만으로 전체 게임의 정확성을 보장하지 않는다.
- strict/default/full 이름 노출과 힌트 공개는 독립적으로 계산한다. 좌표를 AI로 생성하거나 매번 노선을 재배치하지 않는다.

## 로컬 보존

키: zelda-highpass:oot:progress:v1. schemaVersion과 contentVersion을 별도로 검사한다. 현재 지원은 스키마 1이며, 과거 형식은 아직 없으므로 근거 없는 마이그레이션을 만들지 않았다. 미지원 스키마/콘텐츠 버전은 원본을 보존하고 거부한다. 새 버전을 도입할 때 마이그레이션과 테스트를 추가한다.

읽기·쓰기 차단, 손상 JSON, 잘못된 ID, 중복 ID, 1MB UTF-8 제한을 처리한다. 손상 원문을 자동 초기화하지 않으며 내려받기 기회를 제공한다. 설정 변경은 현재 탭에 적용할 수 있지만 영구 저장 실패를 고지한다. 저장 이벤트로 다른 탭 변경을 반영하고, 저장 직전 스냅샷이 다르면 덮어쓰지 않는다.

SSR와 첫 CSR는 중립 UI로 맞춘 뒤 저장 상태를 읽는다. 파일 가져오기는 검증 → 교체 확인 → 적용 순서이며, 확인 전 원본을 바꾸지 않는다.

## 서버 보존

서버 읽기/저장 Action마다 getUser로 인증을 확인하고 user_id는 서버에서 결정한다. 공략 ID/버전은 parseProgress로 재검사하며 같은 규칙 함수로 추천을 다시 계산한다. DB는 RLS로 다른 사용자의 읽기·변경을 막는다.

서버 기록 확인 후 로컬로 가져오거나 현재 로컬 기록을 서버에 저장한다. 초기 코드에는 자동 동기화/병합이 없다. revision=0은 최초 삽입, 이후는 읽은 revision 조건으로 업데이트한다. DB trigger가 revision을 증가시킨다. 동시 변경·중복 최초 삽입은 충돌로 안내하고 재조회하게 한다.

로그아웃은 서버 세션을 끝내며 로컬 기록을 삭제하지 않는다. 서버 장애 시 로컬 백업을 계속 사용할 수 있다. 계정 삭제 UI·보유 기간 정책은 공개 전 별도 작업이다.

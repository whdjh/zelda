# 콘텐츠 구조·한국어 검색 전략

## 목표

입문자는 검색에서 바로 해당 지점으로 들어오고, 서비스 내부에서는 현재 진행 역과 점진적 힌트로 돌아간다. SEO를 위해 가이드 내용을 억지로 수십 페이지로 나누지 않는다.

## 권장 페이지 계층

- `/oot` — 소개 화면 없이 노선·진행 기록·설정을 사용하는 단일 메인 화면.
- `/oot/route` — 기존 주소 호환을 위해 `/oot`로 이동.
- `/oot/route/[stopId]` — 역별 공개 가능한 고유 URL. 서버 렌더 가능한 3줄 목표/개요.
- `/oot/puzzles/[puzzleId]` — 검색 가능한 특정 문제, 처음 화면에는 해답 숨김.
- `/oot/about` — 출처·검증 원칙·비공식 안내.

SEO의 진입점과 앱형 내비게이션 경험을 **같은 콘텐츠 데이터**에서 만들되 UX는 달라도 된다.

## 키워드 가설 (실제 검색량 순위 아님)

- `시간의 오카리나 리메이크 공략`
- `시간의 오카리나 데크나무 공략`
- `시간의 오카리나 코키리의 검`
- `시간의 오카리나 [지역명] 길`
- `시간의 오카리나 [퍼즐명] 힌트`
- `시간의 오카리나 던전 순서`

키워드별 실측 검색량은 아직 없음. 순위를 임의로 조작하지 않는다. 제목과 본문은 실제 게임 내 용어에 일치시키고, 유사 검색 표현은 별칭 메타데이터로 관리.

## 작성 규칙

- '어디에서' '무엇을' '왜 지금'을 먼저.
- 요약은 최대 세 개의 짧은 행동 문장으로, 한 문장에 한 행동.
- 1차 화면은 해답/미래 스토리/나중에 나올 보스를 숨긴다.
- 상세 힌트는 사용자 요청으로만 연다.
- 검색 결과 요약문에 퍼즐 정답이 노출되지 않도록 주의.
- 공략 유효 버전·검증 상태·공식 한국어 명칭을 함께 관리.

## 콘텐츠 제작 파이프라인

자료 수집 → 사실 단위 추출(출처 기록) → 비교표 → 추천 경로 결정(근거) → 자체 한국어 요약 작성 → 직접 플레이 교차 검증 → 게시 → 변경 이력 관리.

대량 AI 생성 페이지를 사실 검증 없이 발행하지 않는다.

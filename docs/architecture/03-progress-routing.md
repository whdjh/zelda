# 진행도·상태 저장·규칙 기반 경로

> 현재 사용은 비로그인 로컬 기록이다. 아래 Supabase 부분은 공략 제작 이후 연결할 준비 코드의 설계다.

## 구분

| 데이터 | 위치 |
| --- | --- |
| 게임 사실·출처·판본·힌트 본문 | 정적 content 폴더 |
| 선택 역·열린 시트·백업 확인·통신 상태 | 해당 UI의 useState |
| 브라우저 완료·조건·힌트 ID·스포일러 | useProgress + localStorage v1 |
| 로그인 사용자·인증 쿠키 | Supabase Auth + SSR 클라이언트 |
| 사용자별 서버 진행도·힌트 ID | user_progress 스냅샷 + revision |

## 규칙 계산

`selectRoute`는 선택 목적지(기본 엔딩)에서 필요한 조건을 역으로 탐색한다. 이벤트 선행 역과 아직 보유하지 않은 장비의 획득 경유를 연결한다. 완료한 역에서는 탐색을 멈추며 이전 역을 자동 완료하지 않는다. 장비를 확인하면 해당 획득 경유선이 제거되고 남은 그래프의 위상 단계와 분기 배치를 재계산한다.

- `requirements`: 미기록 선행 역·장비·시대. `availableIds`는 준비가 확인된 후보이며 **완료 버튼의 허용 여부가 아니다**.
- `neededIds`: 목적지까지 남은 경유. `dependencies`: 현재 남은 연결. `layers`: 완료·보유 상태에 따라 재구성한 단계별 배치.
- 추천은 필요한 후보 중 준비가 확인된 첫 구간, 없으면 남은 연결의 시작 구간이다. 동률은 콘텐츠 순서다. 이동 거리·시간 최적화 알고리즘으로 표시하지 않는다.
- 완료 기록은 언제든 직접 수정한다. `conflictIds`는 선행 기록 누락 검사에 남기지만 진행을 막거나 자동 수정하지 않는다.
- strict는 완료·추천 구간만 이름을 공개한다. 기본은 full이다. 정답은 별도 동작 후 렌더한다.
- 조건별 근거와 한계는 [조사 기록](../research/06-route-network.md)에 남긴다. 그래프 라이브러리/AI 좌표 생성은 사용하지 않는다.

## 로컬 보존

키: zelda-highpass:oot:progress:v1. schemaVersion과 contentVersion을 별도로 검사한다. 시대 필드가 없는 기존 스키마 1 기록은 age=unknown으로 읽는다. 선택 목적지 goalStopId는 선택 필드이며 가져올 때 실제 역 ID인지 검사한다. 기본 공개 정책 변경에 따라 이전 default는 full로 읽고 strict 선택은 보존한다. 읽기만으로 원본 JSON을 덮어쓰지 않는다. 빈 초안과의 호환을 위해 contentVersion은 oot-draft-1을 유지했다. 미지원 스키마/콘텐츠 버전은 원본을 보존하고 거부한다. 새 버전을 도입할 때 마이그레이션과 테스트를 추가한다.

읽기·쓰기 차단, 손상 JSON, 잘못된 ID, 중복 ID, 1MB UTF-8 제한을 처리한다. 손상 원문을 자동 초기화하지 않으며 내려받기 기회를 제공한다. 설정 변경은 현재 탭에 적용할 수 있지만 영구 저장 실패를 고지한다. 저장 이벤트로 다른 탭 변경을 반영하고, 저장 직전 스냅샷이 다르면 덮어쓰지 않는다.

SSR와 첫 CSR는 중립 UI로 맞춘 뒤 저장 상태를 읽는다. 파일 가져오기는 검증 → 교체 확인 → 적용 순서이며, 확인 전 원본을 바꾸지 않는다.

## 서버 보존

서버 읽기/저장 Action마다 getUser로 인증을 확인하고 user_id는 서버에서 결정한다. 공략 ID/버전은 parseProgress로 재검사하며 같은 규칙 함수로 추천을 다시 계산한다. DB는 RLS로 다른 사용자의 읽기·변경을 막는다.

서버 기록 확인 후 로컬로 가져오거나 현재 로컬 기록을 서버에 저장한다. 초기 코드에는 자동 동기화/병합이 없다. revision=0은 최초 삽입, 이후는 읽은 revision 조건으로 업데이트한다. DB trigger가 revision을 증가시킨다. 동시 변경·중복 최초 삽입은 충돌로 안내하고 재조회하게 한다.

로그아웃은 서버 세션을 끝내며 로컬 기록을 삭제하지 않는다. 서버 장애 시 로컬 백업을 계속 사용할 수 있다. 계정 삭제 UI·보유 기간 정책은 공개 전 별도 작업이다.

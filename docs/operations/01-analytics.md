# 분석·SEO 운영 — MAU는 결과, 사용자 가치가 원인

## 주요 성과 목표

장기 목표는 높은 MAU이나 출시 전 정확한 목표 수치와 시장 규모는 **미확인**. 초기에는 사용자가 '다음 행동 찾기/막힌 문제 해결'을 실제로 달성하는지를 먼저 검증한다.

## 핵심 지표 정의

| 구분 | 지표 | 사용 이유 |
| --- | --- | --- |
| 획득 | Search Console 검색 노출/클릭/검색어 | 한국어 정보 수요 발견 |
| 활성 | GA4 MAU(최근 28일/달력 월 등 정의 통일), 활성 사용자 | 프로젝트 도달 규모 |
| 사용 | 역 상세 열람 비율, 힌트 1~3단계 개방 | 실제 상황에서 쓰이는 기능 파악 |
| 유지 | 7일·28일 재방문(측정 가능한 범위) | 플레이 중 다시 방문하는가 |
| 품질 | 오답 신고/힌트 이탈/저장 실패 | 가치가 무너지는 지점 식별 |

GA4 UI에 표시되는 MAU 기간 정의를 문서로 고정. 일일 오픈 수나 페이지뷰를 'MAU'라고 말하지 않는다.

## 추천 최소 이벤트

```
route_viewed { game: 'oot' }
stop_opened { stop_id: '...', verification: '...' }
hint_revealed { puzzle_id: '...', level: 1|2|3 }
stop_completed { stop_id: '...' }
progress_imported { success: boolean }
route_feedback { stop_id: '...', category: 'wrong'|'unclear'|'helpful' }
```

개인별 이동 기록/유저가 입력한 자유 텍스트는 분석 서비스로 보내지 않는다. 이벤트를 과도하게 많이 정의하지 않는다.

## SEO 테스트

- 현재 메인 URL의 `<title>`과 설명만 관리한다. 역/퍼즐별 페이지는 만들지 않는다.
- 검색 크롤러가 사용할 HTML 본문에 공개 가능한 정보를 제공. 모든 정보를 클라이언트 렌더로만 표시하지 않음.
- 숨겨야 하는 정답은 SEO 메타나 OG 이미지에 넣지 않음.
- Sitemap, robots 설정, 페이지 오류, 모바일 성능 확인.
- 검색어는 `공략`, `아이템명`, `막힌 상황` 같은 의도별로 묶어 관찰.

## 검증 프레임

- 유입 많고 재방문 적음: 해결 후 더 쓸 가치가 없는가? 정상적으로 답을 찾고 떠난 것일 수도 있음.
- 유입 적고 반복 사용 높음: 콘텐츠 주제와 검색 노출 개선이 기회.
- 힌트 3 개방률 높음: 어려운 퍼즐인지, 1·2단계의 정보량이 부족한지 조사.
- MAU 증가·정답 오류 증가: 품질 악화가 장기 신뢰를 무너뜨릴 수 있음.

## 유의사항

초기 소수 테스트 계정/내부 테스터를 일반 사용자 지표로 혼합하지 않는다. 분석과 정책 고지는 `docs/quality/02-rights-privacy.md`에 따른다.
